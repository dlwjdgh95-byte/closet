# 추천 로직

**날씨와 TPO로 거르고 → 밸런스 점수를 매기고 → 다양하게 고르는** 세 단계입니다. 날씨는 점수에 섞지 않는 최우선 조건입니다. 코드는 `closet/recommend.py`, 조정 값은 `data/scoring.yaml`에 있습니다.

## 실행

```
python3 -m closet --tpo commute --temp 8          # 출퇴근, 체감 8℃
python3 -m closet --tpo date --temp 21 --rain     # 데이트, 비
python3 -m closet --tpo social                    # 기온 생략 시 오늘 서울 날씨(Open-Meteo)
python3 -m closet --tpo commute --temp 8 --json   # JSON 출력
python3 -m closet --tpo commute --temp 8 --prompt # LLM에 넘길 프롬프트 출력
python3 -m unittest discover tests                # 테스트
python3 scripts/build_page.py --standalone        # 옷장 페이지(web/dist/closet.html) 만들기
```

TPO는 `commute`(출퇴근), `social`(친목모임), `date`(데이트)입니다. 다른 지역은 `--lat`, `--lon`으로 지정합니다.

## 1. 필터 (날씨 최우선)

| 조건 | 규칙 |
|---|---|
| TPO | 모든 옷의 격식이 TPO 범위 안 |
| 기온 | 체감기온을 목표 보온도(1~5)로 바꾸고, 슬롯별 허용 폭 안의 옷만 남김 |
| 아우터 | 목표 보온도 4 이상이면 필수, 1이면 없음, 그 사이는 선택 |
| 비 | 스웨이드 제외 |

허용 폭은 아우터 ±1, 상의·하의·신발은 -2~+1입니다. 레이어링을 다루지 않으므로 한겨울에는 얇은 셔츠가 후보에서 빠집니다.

조합 단위로도 한 번 더 봅니다. 가장 따뜻한 윗옷(아우터 또는 상의)의 보온도가 목표와 **정확히 같은 조합을 먼저** 다 보고, 그것만으로 추천 개수를 못 채울 때에만 한 단계 덜 맞는 조합으로 넓힙니다. 밸런스 점수가 아무리 높아도 날씨에 덜 맞는 조합이 딱 맞는 조합을 앞지르지 못합니다.

## 2. 점수

날씨를 통과한 코어 4슬롯(아우터·상의·하의·신발) 조합마다 축별 점수(0~1)를 내고 가중 평균합니다.

| 축 | 가중치 | 높은 점수 | 감점 |
|---|---|---|---|
| 색 | 0.35 | 기본색 바탕에 포인트 색 한 계열, 위아래 명암 대비 | 유채색 두 계열 이상, 패턴 2개 이상 |
| 격식 | 0.30 | 옷 간 격식 차이 1 이하, 평균이 TPO 목표에 가까움 | 격식 차이 2 이상 |
| 핏 | 0.20 | 위아래 한쪽은 여유 있고 한쪽은 정돈됨 | 위아래 모두 슬림 또는 오버핏, 상의보다 좁은 아우터 |
| 무드 | 0.15 | 같은 무드(1.0), 어울리는 무드(0.75) | 충돌하는 무드(0) |

무드는 옷끼리 둘씩 비교한 값의 평균입니다. 옷의 무드는 `mood_override`가 있으면 그것, 없으면 브랜드 프로필의 무드입니다.

## 3. 선택

- 점수순으로 고르되, 이미 고른 코디와 **한 벌만 다른 조합은 건너뜁니다**. 같은 코디에 신발만 바꾼 결과가 나열되는 것을 막습니다.
- 액세서리는 코어 코디가 정해진 뒤 무드·격식·색이 가장 잘 맞는 것 하나를 붙입니다. 맞는 것이 없으면 붙이지 않습니다.
- 결과마다 축별 점수와 이유를 함께 보여 줍니다.

## 옷장 페이지

`scripts/build_page.py`가 조건(TPO × 목표 보온도 × 비)마다 상위 10개 코디를 미리 계산해 `web/template.html`에 넣어 HTML 한 장을 만듭니다. 옷장 문을 열면 순위대로 코디가 나오고, 옷은 종류·색·패턴·핏을 따라 그린 그림으로 보여 줍니다. 옷장 데이터를 바꾸면 다시 만들어야 합니다.

옷장은 실사 재료를 씁니다. `web/assets/`에 닫힌 옷장 사진(`closed.jpg`), 문 여는 영상(`opening.mp4`), 영상 마지막 장면(`inside.jpg`)이 있고, 빌드할 때 페이지 옆 `assets/` 폴더로 복사됩니다. 닫힌 사진은 영상 첫 장면과, `inside.jpg`는 영상 마지막 장면과 같아야 화면이 끊기지 않습니다. 영상은 빈 옷장 안을 정면에서 비추며 끝나고, 추천 옷은 위아래 두 칸으로 놓입니다. 위칸은 그 장면의 옷걸이 봉(위 11%, 좌우 24%~75.6%)에 겉옷과 윗옷을 걸고, 아래칸은 뒤판 놋쇠 고리에 바지(와 머플러)를 걸고 신발·가방을 바닥에 둡니다. 영상을 바꾸면 `web/template.html`의 `.set` 위치를 새 장면에 맞춰야 합니다. 영상을 틀 수 없는 환경에서는 사진끼리 바로 넘어갑니다.

날씨는 claude.ai에서 페이지를 여는 사람의 AccuWeather 커넥터로 불러옵니다(아티팩트 `mcp` 기능, 일별 예보 `widgets-daily-claude`). 장소는 `data/weather.yaml`(기본 서울), 비 기준은 `data/scoring.yaml`의 `rain_probability`입니다. 오늘 낮 체감기온을 슬라이더에, 강수확률이 기준 이상이면 "비"를 켭니다. 저녁 7시가 지나면 내일 낮 예보를 씁니다. 직접 바꾸면 그대로 두고 "날씨대로" 버튼으로 되돌립니다. 커넥터가 없거나 허용되지 않으면 지금처럼 직접 고릅니다.

## LLM 단계 (선택, 미연결)

`closet/llm.py`는 상위 후보와 브랜드 관점을 담은 프롬프트만 만듭니다. API 호출은 아직 붙이지 않았습니다. 규칙 점수만으로 부족한 부분이 확인되면 연결합니다.
